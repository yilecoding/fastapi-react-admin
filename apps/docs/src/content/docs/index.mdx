## What's in the box

<CardGrid>
  <Card title="Row-level data permissions" icon="seti:lock">
    Beyond menus and buttons, a role decides which **rows** a user sees. A department manager opening the user list only gets their own department.
    [How it works →](features/data-permissions/)
  </Card>
  <Card title="Tabs that keep their state" icon="laptop">
    Built on React 19's `<Activity>`: a half-filled form, the page you were on and an expanded tree are still there when you switch back. Filters live in the URL, so a refresh keeps them too.
    [How it works →](features/multi-tab/)
  </Card>
  <Card title="Approval workflow" icon="list-format">
    Form designer and flow tree with or-sign / co-sign, send back, transfer, take back, add approvers and timeouts.
    [How it works →](features/approval-workflow/)
  </Card>
  <Card title="An AI assistant that can't overreach" icon="puzzle">
    Tool calls run as the signed-in user, inside their permissions and data scopes. Writes are previewed and run only after the user confirms; every call is audited.
    [How it works →](features/ai-assistant/)
  </Card>
  <Card title="Large files, handled" icon="document">
    Local disk or S3-compatible storage, instant upload by hash, parallel chunks and resume after a page refresh.
    [How it works →](features/file-storage/)
  </Card>
  <Card title="Pick your database" icon="setting">
    PostgreSQL, SQL Server or MySQL with the same code and the same migration chain.
    [How it works →](features/databases/)
  </Card>
</CardGrid>

## Tested against real dependencies

The backend suite (1,400+ pytest tests) runs against a real database and Redis on every CI run — on both PostgreSQL and SQL Server. 150+ Playwright tests drive a real browser against the real API and database, with no mocks. The [E2E report](https://yilecoding.github.io/fastapi-react-admin/e2e/) from every `main` run is public.
