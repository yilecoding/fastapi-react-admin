<SectionTitle id="有什么" eyebrow="WHAT'S IN THE BOX" title="内部系统迟早要做的那几样">

用户、角色、部门是容易的那部分。下面这些，才是每个项目都要从头再造一遍的。

</SectionTitle>

<div class="features">
  <Feature title="权限细到数据行" icon="rows" href="features/data-permissions/" more="怎么做的">
    菜单、按钮之外还有数据范围：角色决定一个人能看到**哪几行**。同一张用户表，部门经理打开只看得到本部门的人。
  </Feature>
  <Feature title="多页签切回来状态还在" icon="tabs" href="features/multi-tab/" more="怎么做的">
    基于 React 19 的 `<Activity>`：填了一半的表单、翻到的页码、展开的树，切走再切回来都还在；筛选条件写在 URL 里，刷新也不丢。
  </Feature>
  <Feature title="审批流" icon="flow" href="features/approval-workflow/" more="怎么做的">
    表单设计器 + 流程树，或签 / 会签、退回、转交、撤回、加签、超时处理。
  </Feature>
  <Feature title="不越权的 AI 助手" icon="sparkles" href="features/ai-assistant/" more="怎么做的">
    工具调用以当前登录用户的身份执行，受同一套权限和数据范围约束；写操作先预览、用户确认后才执行，每次调用都留审计。
  </Feature>
  <Feature title="大文件上传" icon="upload" href="features/file-storage/" more="怎么做的">
    本地磁盘或 S3 兼容存储，按哈希秒传，分片并行上传，刷新页面后断点续传。
  </Feature>
  <Feature title="数据库三选一" icon="database" href="features/databases/" more="怎么做的">
    PostgreSQL、SQL Server、MySQL 用同一套代码、同一条迁移链。
  </Feature>
</div>

<CtaBand title="五条命令，在本地跑起来" primary={{ text: '快速开始', href: 'getting-started/quick-start/' }} secondary={{ text: '这是什么，和常见模板有什么不同', href: 'getting-started/introduction/' }}>

```bash
docker compose -f docker-compose.dev.yml up -d          # PostgreSQL + Redis
pnpm install:all
cp apps/api/backend/.env.example apps/api/backend/.env
pnpm db:init                                            # 建表 + 种子数据
pnpm dev                                                # 打开 http://localhost:8888
```
