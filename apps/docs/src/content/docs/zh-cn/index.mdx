## 有什么

<CardGrid>
  <Card title="权限细到数据行" icon="seti:lock">
    菜单、按钮之外还有数据范围：角色决定一个人能看到**哪几行**。同一张用户表，部门经理打开只看得到本部门的人。
    [怎么做的 →](features/data-permissions/)
  </Card>
  <Card title="多页签切回来状态还在" icon="laptop">
    基于 React 19 的 `<Activity>`：填了一半的表单、翻到的页码、展开的树，切走再切回来都还在；筛选条件写在 URL 里，刷新也不丢。
    [怎么做的 →](features/multi-tab/)
  </Card>
  <Card title="审批流" icon="list-format">
    表单设计器 + 流程树，或签 / 会签、退回、转交、撤回、加签、超时处理。
    [怎么做的 →](features/approval-workflow/)
  </Card>
  <Card title="不越权的 AI 助手" icon="puzzle">
    工具调用以当前登录用户的身份执行，受同一套权限和数据范围约束；写操作先预览、用户确认后才执行，每次调用都留审计。
    [怎么做的 →](features/ai-assistant/)
  </Card>
  <Card title="大文件上传" icon="document">
    本地磁盘或 S3 兼容存储，按哈希秒传，分片并行上传，刷新页面后断点续传。
    [怎么做的 →](features/file-storage/)
  </Card>
  <Card title="数据库三选一" icon="setting">
    PostgreSQL、SQL Server、MySQL 用同一套代码、同一条迁移链。
    [怎么做的 →](features/databases/)
  </Card>
</CardGrid>

## 测试连的是真实依赖

后端 1400 多条 pytest 每次 CI 都连真实数据库和 Redis 跑，PostgreSQL 和 SQL Server 各跑一遍全量；150 多条 Playwright 用例用真浏览器打真实的接口和数据库，不用 mock。`main` 每次跑完的 [E2E 报告](https://yilecoding.github.io/fastapi-react-admin/e2e/)都公开。
