## 每项功能在哪个菜单？手机上能用吗？

桌面端直接加载网页端的构建产物，**网页端有的桌面端都有**，所以下表只对比网页和手机 App。「插件」一列是 `apps/api/backend/plugin/` 下的目录名，空着的是核心功能。菜单名是种子数据里的，部署方可以自己改。

| 功能 | 网页端菜单 | 插件 | 手机 App |
|---|---|---|---|
| 登录与安全 | 个人中心 · 系统监控 → 在线用户 · 系统管理 → 参数配置 | 手机验证码登录要 `sms`，第三方登录要 `oauth2` | 密码 / 手机验证码登录，能输动态码；被强制开二次验证、还没绑定的人要先到网页端绑定 |
| 用户 · 角色 · 部门 · 菜单 | 系统管理 → 用户 / 角色 / 部门 / 菜单管理 | | 用户列表 → 详情 → 删除（作为可照抄的范式） |
| 数据权限 | 系统管理 → 数据权限 | | 过滤在后端，App 调到的列表一样受约束 |
| 多页签 · 工作台 | —（外壳）· 仪表盘 | | 首页是固定的公告 + 我的审批 + 入口，不能编辑布局；没有多页签 |
| 导入导出 | 各列表页的工具栏 | | 无 |
| 文件与存储 | 系统管理 → 文件管理 / 存储管理 | | 只能看公告的附件 |
| 审批流 | 审批 → 审批中心 / 流程定义 / 实例监控 | `workflow` | 待办、详情、发起 |
| 站内消息 · 通知公告 | 顶栏铃铛 · 系统管理 → 通知公告 | `notification` · `notice` | 能看，不实时（进入页面或下拉时刷新） |
| 通知渠道 · 短信 | 消息推送 → 通知策略 / 投递记录 · 短信 → 短信配置 / 发送日志 | `notification` · `sms` · `email` | 无 |
| AI 助手 | AI 助手 | `ai` | 无 |
| 能力开放 | 能力开放 → 应用管理 | `open` | 无 |
| 定时任务 | 任务调度 → 任务管理 / 任务记录 | | 无 |
| 参数配置 · 数据字典 | 系统管理 → 参数配置 · 数据字典 | `config` · `dict` | 无 |
| 日志与审计 | 日志管理 → 登录日志 / 操作日志 / 数据变更 | | 无 |
| 监控 | 系统监控 → 在线用户 / 服务器监控 / Redis 监控 | | 服务器监控 |

手机 App 目前只在 Android 上手工验收过，范围和限制见[桌面端与移动端](/features/clients/#移动端还没做什么)。

## 工程规矩写在哪

仓库把规矩和踩过的坑写在代码旁边：根目录的 [`CLAUDE.md`](https://github.com/yilecoding/fastapi-react-admin/blob/main/CLAUDE.md) 加 40 多份模块分册（`AGENTS.md`），按任务索引（「加列表页」「改权限模型」「写迁移」）。每条都是同一个格式——现象、原因、修法、证明它的实测或测试；CI 里跑 `pnpm ctx:check`，文档指向的文件、脚本或 testid 不存在了就报错。
