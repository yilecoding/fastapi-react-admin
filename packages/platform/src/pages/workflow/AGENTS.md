## 共用件

| 文件 | 谁在用 |
|---|---|
| `form-renderer.tsx` | 发起抽屉 · 审批详情 · 设计器预览（三处**同一个**，模式靠 `mode` + `perms` 切） |
| `flow-view.tsx` + `flow-edit.ts` | 设计器（可编辑）· 详情和发起页的只读流程图 |
| `instance-sheet.tsx` | 审批中心 · 实例监控（详情抽屉） |
| `pickers.tsx` | 选人 / 选部门，数据走审批的通讯录接口 |

## 🔴 按钮只按能力信封出

详情接口的 `capabilities` 和执行接口用的是**同一个服务端函数**。前端不根据实例状态、
「我是不是发起人」自己推导按钮 —— 推出来的规则迟早和服务端漂移，而漂移的表现是
「按钮在、点了报 409」或者更糟的「该有的按钮没有」。

## 详情和发起都是抽屉，开着哪个写在 URL 里

`/workflow/inbox?id=…` 打开详情、`?start=编码` 打开发起（硬纪律 2）。
消息中心里的审批通知直接链到 `?id=`，后端 `detail_link()` 拼的就是这个地址 ——
**改路由要两边一起改**，链接对不上时消息中心会把那条通知当成「不可点」（`isValidPath`），不报错。

页面组件不能 `useNavigate()`（硬纪律 1），发起成功后「跳到详情」是改自己的 search：
`{ start: undefined, tab: 'initiated', id }`。

## 选人控件分了两层

`_shared/user-select.tsx` 是通用的（数据源由调用方给），`pickers.tsx` 绑审批的通讯录接口。
部门页的负责人选择绑 `/sys/users` —— 部门页是底座，不能依赖一个可以卸载的插件。

## 设计器

- 选中的节点 / 字段 / 当前步骤都进 URL（`sel` / `step`），刷新不丢
- 草稿是 `draft ?? baseline` 两层，后台重取不会冲掉没保存的改动；离开前有未保存修改要确认
- 一个新建的审批节点**没有**审批人规则，规则编辑器里也什么都不选中。
  第一版默认高亮「部门主管」而模型里是空的，发布时报「未设置审批人」，看起来像校验坏了
- 字段排序用上 / 下按钮，没用拖拽：`@dnd-kit` 只是 `packages/ui` 的依赖，
  platform 要用得先在 `package.json` 里声明（根 CLAUDE.md 依赖箭头那条）
- 条件编辑器只编辑一层「全部满足」；打开编辑不了的条件（手写的 `any` 嵌套）**不改写它**

## 新菜单的图标要进 `shell/icon-registry.tsx`

种子菜单写的是 Iconify 名（`mdi:file-sign`），没映射的回落到一个圆点并在**开发期控制台**告警 ——
界面不报错，只是侧边栏上一个点。E2E 跑的时候 vite 日志里能看到那条 warn。

## 联动的前端副本（`form-rules.ts`）

`engine/form.py: form_rules` 的副本，只为「填的时候当场看到」。存什么、走哪条分支以服务端为准。

- **金额合计用 BigInt 按 10^6 放大求和**：浮点加法会把 0.10 + 0.20 加成 0.30000000000000004。
  E2E「表单联动」那条断言的就是 `0.30`
- 🔴 **「自动计算」框的显示条件是「这个人在这一步能填它」，不是 `mode === 'edit'`。** 发起页用的是
  `mode="view"` + 开始节点权限（可填的字段是 `editable`），第一版只认 `mode === 'edit'`，于是发起人看到的
  计算字段是一行普通只读值、没有「自动计算」提示 —— E2E 抓到的
- 必填检查（`missingRequired`）同样跳过不显示的和自动计算的字段（同后端 `validate_form_data`）
- 变异验证：渲染器里去掉「不显示的字段跳过」，E2E「表单联动」当场红（`Expected: 0, Received: 1`）

## 审批进度按「节点 + 轮次」分组

退回之后同一个节点会走第二遍（后端那份「只能按轮次数」）。`progress.ts` 按 `${node_id}:${batch}` 分组：
两轮各是一步，「退回给 发起人」「已重新提交」都挂在对应那一步的人身上。
依次审批的当前步骤里，没轮到的人从 `detail.waiting` 来，标「等待中」。

## E2E：选人浮层别用 Esc 关

单选的选人控件选完浮层自己关。在弹窗里按 Esc 关浮层，**会连弹窗一起关掉**，后面的提交按钮找不到，
报的是 `locator.click: Test ended`（「改办理人」那条踩过）。选完断言一下触发器上显示了名字就行。
多选（加签选人）浮层不会自己关：点一下弹窗标题收起来再点提交（E2E「加签」那条这么写的）。

## 发起草稿：自动保存要能「停」

`start-sheet.tsx: useDraftAutosave` 停手 1.5 秒存一次。🔴 提交那一刻先 `stop()`：防抖里排着的那次保存要是在
提交成功**之后**才发出去，服务端刚删掉的草稿又被存回来，下次打开「已恢复你没提交的内容」，而那张单其实已经交了。
全清空时删草稿而不是存一份空的。E2E「草稿：关掉再打开内容还在…」断言了「提交后再打开是空的」。

从草稿恢复的附件手上只有 ID：`AttachmentRow` 按 ID 调 `GET /sys/files/{id}` 现查名字（上传人自己读得到，
见 file 分册「私有文件谁能读」），读不到才显示「（文件已删除）」。

## 第二轮代码审查修掉的前端问题

- 🔴 **`form-rules.ts` 原来对数字串 `Number()`**：人员 / 部门字段的值是雪花 ID，转 double 被舍入，
  相邻两个 ID 变成同一个数 → 「部门不属于 X」前端成立、后端不成立，提交被一个看不见的必填字段挡住（硬纪律 6）。
  现在按十进制字符串精确比（`toDec` / `cmpDec`），和后端 `Decimal` 同口径
- **附件上传期间在别的字段打的字，传完被盖回去**：上传回调用的是开始上传那一刻闭包里的表单。
  `FormRenderer` 的 `set` 改成合并最新的值（ref）。E2E 用 `page.route` 把上传拖慢 1.5 秒复现，变异验证过
- **草稿**：提交 / 清空前 `await draft.stop()` 等**正在路上**的那次保存落地（只拦没触发的防抖不够）；
  「重新发起」不碰草稿（不自动存、提交带 `keep_draft`），那份草稿是另一张没写完的单
- **点发布问题跳不过去**：连着调 `onStep` 再 `onSel`，两次都拿同一个旧 `search` 拼地址，第二次把 step 写回去。
  改成一次 `onLocate(step, sel)`。E2E 变异验证过
- **错误弹两遍**：调用处自己 `toast.error`，全局 `MutationCache.onError` 又弹一条。审批的 mutation 都标了
  `meta: { suppressErrorToast: true }`（只给「调用处自己弹」的标）
- 新选项的值按「个数 + 1」生成会和已有的撞上（删过一个再加）；改成找一个没用过的，发布校验也拦重复值
- 附件名查不到：只有 404 才显示「已删除」，别的错误显示「没取到」+ 重试（硬纪律 9）


## AI 预审面板（`ai-review-panel.tsx`）

详情抽屉「申请内容」上方。数据单走 `GET /instances/{pk}/ai-review`（预审中每 3 秒轮询，出结论就停）——
不放进详情接口：轮询详情会每 3 秒重跑一遍预告试算。query key 挂在 `detail(id)` 下面，办完动作失效详情时一起重取。

🔴 **只有服务端明确说「不给」才什么都不画**：`visible: false`（发起人）或 `status: null`（没开 / 没审过）。
`failed` / `timeout` 一定要画成失败 + 「重新预审」—— 画成没有的话，审批人会以为这张单根本没开预审。
E2E `workflow-ai-review.spec.ts` 用 `page.route` 固定「有结论 / 失败」两种返回；变异验证过：把失败那一支改成
`return null`，「失败显示原因 + 重新预审」那条当场红。

设计器里的开关在「基础信息」这一步，写的是 `model.aiReview`；关掉时**保留要点原文**（重新打开不用重写）。

### 点理由定位到字段 · 读了几份附件

理由前面的字段名是按钮（`onLocate`），点了在**详情抽屉自己的滚动区**里找 `[data-field-id]`、手算 `scrollTop`、外框闪 1.6 秒
（`instance-sheet.tsx: locateField`）。不用 `scrollIntoView`（会连外层能滚的祖先一起滚），不用 `document.querySelector`
（硬纪律 5）。字段的锚点 `data-field-id` 在 `form-renderer.tsx` 的三种外框上都有，**不拿 testid 当业务锚点**。
对查看人隐藏的字段服务端早就裁掉了，不在 schema 里的字段名不画成按钮。
下面一行写「参考了 N 份附件 · 其中 M 份没读出内容」—— 让审批人知道模型的结论是基于哪些东西给的。

E2E（`workflow-ai-review.spec.ts`）变异：抽屉不传 `onLocate` · 定位后不闪，各自红。

## 实例监控：AI 预审一致率（`workflow-monitor/ai-review-stats.tsx`）

工具行的按钮打开抽屉，开着写在 URL（`stats=1`）。🔴 **口径原样写在抽屉顶上**（和后端 `agreement_stats` 一字不差）：
一个没写口径的百分比，每个人按自己的理解读，拿它决定要不要让 AI 自动同意就是在赌。按模型分行；没有可比的单显示「—」。
390 宽下表格横向滚，但「一致率」在第三列、首屏就看得见。截图时注意抽屉有滑入动画，等它停了再截（中途截到的是半透明的）。


## 设计器：一句话生成（`workflow-definition/ai-design-dialog.tsx`）

工具条「AI 生成」→ 弹窗写一句话 → 结果换掉草稿里的**表单和流程**，名称 / 分组 / `model.aiReview` 留着（那是管理员在「基础信息」里定的）；
发布校验的问题照常列出、点一下定位。服务端什么都没存，不满意就不保存。

- 🔴 **生成要几十秒，中途关掉弹窗 = 不要这次的结果**（`openRef`）。不丢的话，人已经接着手动改了，半分钟后整张表单被换掉
- 失败挂在弹窗里（`QueryError` + 重试），描述留着改一改再试（硬纪律 9）

E2E `workflow-ai-design.spec.ts`（`page.route` 固定生成接口的返回）。变异各打红：关了弹窗照样用结果 · 生成结果把 `aiReview` 换掉 · 不列问题。

## 发起页：AI 帮我填（`ai-fill-panel.tsx`）

面板收材料（一段话 / 一份文件），服务端只回值；**合并在发起页**（`start-sheet.tsx: mergeAi`）：只填还空着的字段，已经有内容的不动、告诉人动了几项。
填进去的字段下面挂「AI 填的，请核对 · 没问题」（`FormRenderer` 的 `marks`）。

- 🔴 **没核对不许提交**：每个标记要么点「没问题」、要么人自己改过（改了就算核对过）。不拦的话「AI 填的」只是个装饰
- 🔴 **标记跟着草稿存**（`saveDraft(code, form, aiFilled)`）：只放在组件状态里，关掉再打开值还在、标记没了
- 「清空重填」连标记一起清

E2E `workflow-ai-fill.spec.ts`（`page.route` 固定填单接口）。变异各打红：覆盖已经填了的字段 · 标记不存草稿 · 提交不拦 · 改了字段不算核对。

## AI 自动同意（设计器 `flow-designer.tsx: AiApproveEditor` · 进度 `progress.ts`）

- 节点属性里的开关：没开 AI 预审 / 不是或签时**禁用**并说为什么（发布校验也拦）；开了之后两个门槛（单数 · 百分比）
- 🔴 进度里那一步画成「AI 自动同意」、人那一栏写「没经手」，备注是模型名 + 依据。不能画成「某某 已同意」（他没同意过），
  也不能画成「已跳过」（这一步是被同意了的）。判据：这组待办全部取消、而且这个节点上有一条之后的 `ai_approve` 记录

E2E `workflow-ai-approve.spec.ts`（详情用 `route.fetch()` 取真接口再改成被 AI 同意过的形状）。变异各打红：那一步照普通分组画 · 没开预审也能开开关。

🔴 **两个门槛框不能每敲一个键就夹到范围里**（代码审查查出来的）：清空后打「95」，「9」先被夹成 80、再敲「5」成了 805 → 100，
门槛被静默设成 100%。`BoundedNumber`：打字时只交出落在范围里的值，失焦再夹。E2E 用 `pressSequentially` 一个键一个键地打 ——
`fill()` 是一次性写进去的，旧代码上照样绿；改成逐键之后旧代码当场红（`Received: "2050"`）
### 代码审查（2026-10-24）修掉的发起页填单问题，E2E 都在旧代码上红过

- 🔴 **点了「开始填」之后打的字被冲掉**：合并用的是点按钮那一刻闭包里的表单（模型要十几秒）。
- 🔴 **附件传完那一刻，AI 刚标上的「请核对」全没了**：上传回调用的是选文件那一刻的 `onChange`，拿那一刻的表单比，
  AI 填的值全被当成「人改过」—— 没核对的值就能提交了。
  两条一起修：`mergeAi` / `changeForm` 都读 `formRef`（每次渲染和每次改都更新），不读闭包里的 `form`
- **AI 填的字段被显示条件隐藏了，提交永远被拦**：它的「没问题」画不出来。拦提交只看显示着的那些标记（`pendingMarks`）；
  隐藏字段的值服务端本来就不存
