| 文件 | 管什么 |
|---|---|
| `cards/registry.ts` | 卡片注册表：id · 标题 · `available`（权限） · 默认宽度 / 显隐 · 组件。**顺序 = 默认布局的顺序** |
| `card-shell.tsx` | 卡片外壳（标题行 / 动作区 / 加载 · 错误 · 空态），**所有卡片共用这一份** —— 换皮只动它 |
| `cards/*.tsx` | 每张卡片的取数和内容，不管长相 |
| `layout.ts` | 纯逻辑：存的布局 × 现在能用的卡片 → 界面上的布局（单测 `layout.test.ts`） |

| `../../auth/user-preferences.ts` | 个人偏好的 query / mutation（`GET / PUT /sys/users/me/preferences/{key}`），不是工作台专用的 |

加一张卡片 = 注册表加一项 + `cards/` 下一个内容组件（外壳用 `DashboardCard`）。
已经存过布局的人会在**最后**看到它（按它的默认显隐），不用迁移任何人的数据。

## 🔴 读布局失败：错误要看得见，而且**不许编辑**

**症状**（不这么做时）：`GET …/preferences/dashboard.layout` 502，页面照样画出一套卡片 —— 是**默认**布局，
而用户以为「我存的布局没了」；更糟的是这时「编辑工作台」照常可用，改一下点保存，
就拿默认布局把他服务端那份**覆盖掉了**。两步都没有任何报错。

**修法**（`index.tsx`）：读失败时画默认布局 + `dash-layout-error` 错误块（带重试），
`canEdit` 只认「读成功了」（`resolved` 非空）。没存过时接口回 **200 + `value: null`**，不是 404 ——
所以 `error` 只会是真的读失败，不会和「这个人还没存过」混在一个分支里。

**实测证据**：`e2e/tests/dashboard-personalize.spec.ts`「读布局失败」那条用 `page.route` 把那个 GET 打成 502。
两个变异各自当场红：去掉错误块 → 红在「错误块可见」；读失败也允许编辑 → 红在 `toBeDisabled()`。

**保存失败同理**：错误块（`dash-editor-save-error`）留在编辑器里、URL 还是 `edit=true`、草稿不丢。
「保存」写成 `onSettled` 里退出编辑模式的话，失败也弹「已保存」退出去、改动全丢 —— 变异实测那条用例当场红。

## 🔴 没权限的卡片不渲染 —— 判据必须和**取数接口的守卫**一致，粒度到每个查询

#202 之前非管理员打开首页是一排「没有权限」+「仅超级管理员可见」。现在不能用的卡片不进候选也不渲染，
「今日指标」里没权限的那一格也不画。两条容易做错的：

- 🔴 **一个 `Promise.all` 里拼了几个要不同权限的接口，就会整块 403。** 原来的 `scaleStatsQuery` 一次取
  用户数 + 角色数 + 公告数：部门经理（MANAGER）有 `sys:user:list`、没有 `sys:role:list`，实测
  `GET /sys/roles?page=1&size=1` 是 **403**、`/sys/users` 是 200 —— 绑在一起的话他「用户总数」那一格也拿不到。
  现在按权限拆成独立查询（`todayCountQuery(kind)` / `scaleCountQuery(kind)`），各自 `enabled`。
  实测：张伟（MANAGER）的工作台上「今日指标」只有「用户总数 17」一格，没有错误块
- ⚠️ **能看数字 ≠ 能点进日志页。** 日志列表接口要 `log:*:list`，日志页的**路由守卫**要 `log:*:del`。
  卡片按前者决定显不显示，「查看明细 / 全部」链接按后者决定给不给 —— 只有 list 的人点过去只会落到 /403

🔴 **权限码 / 「我是谁」/ 侧边栏都到齐之前，不算可用卡片、也不合并布局，画骨架。** 两种坏法：
`usePerm().can` 在 codes 还没回来时恒为 `false`，那时算出来的默认布局只有人人都有的几张、等 codes 回来又多出统计卡
（读 `auth/use-perm.ts` 得出的，没专门复现）；更直接的是**拿空集合合并布局** —— 合并出来一张卡片都没有，
页面上是「所有卡片都隐藏了」。实测：E2E「菜单 / 权限还没到齐时是骨架」把侧边栏拖慢 3 秒，`resolveLayout` 不等
`ctxReady` 的写法在布局回来、侧边栏没回来的那段时间里画的就是 `dash-empty`（我自己第一版就是这么写的，评审时翻出来的）。
⚠️ 这条用例第一版用 `toHaveCount(0)` 断言「没出现」，把修复改回去**照样绿** —— 它一上来就满足。
要验「一段时间里一次都没出现」，得先等到窗口开始（布局的响应回来）、确认窗口还在（侧边栏没回来），再不重试地数一次。
「我的待办」的可用性跟着侧边栏走（`inSidebar('/workflow/inbox')`）：审批是插件，没装 / 菜单没授权时
那张卡片取数必然 404、「全部」也进不去。

## 布局的兼容规则（`layout.ts`，issue #202「1.0 起的兼容约定」）

| 情形 | 行为 |
|---|---|
| 存的里面有不认识 / 现在不能用的卡片 id | 渲染时忽略 |
| 新加的卡片，存的里面没有 | 按它自己的默认显隐 / 宽度排到最后 |
| 单项字段坏了（宽度拼错、显隐不是布尔） | 那一项回落到卡片的默认值，不连累别的项 |
| 整份认不出来（不是对象 / 没有 `cards` 数组） | 默认布局 + `dash-layout-unreadable` 提示 |
| 保存时，存的里面「现在不能用」的卡片 | **原样带回去**排在后面 —— 权限临时被收走时保存一次，权限还回来那张卡片还是原来的设置 |

🔴 所以**卡片 `id` 发出去之后不能改**：改名 = 所有人这张卡片的设置作废、退回默认值排到最后，不会报错。

**实测证据**：`layout.test.ts` 12 条；E2E「存的布局里有不存在的卡片 id / 没权限的卡片」那条
（存了 `no-such-card` + 普通员工没权限的 `recent-logins`，页面照常、两者都不出现）。
变异：页面不看存的布局（`resolveLayout(null, …)`）→ E2E 5 条红 4 条。

## 编辑模式

- `edit` 进 URL（硬纪律 2），草稿只在组件 state 里、写成 `draft ?? baseline` 两层 —— 后台重取不冲掉没保存的改动；
  刷新时编辑模式还在，草稿回到已保存的那份
- 排序是编辑器里一条**竖列表**，不是在卡片网格里直接拖：卡片宽度不一，网格里拖的落点难以预测，
  键盘拖拽在二维网格里也不好用。网格是草稿的实时预览
- 用了 `@dnd-kit`（platform 的 `package.json` 里声明了，不是借 `packages/ui` 的 —— 根 CLAUDE.md 依赖箭头那条）。
  读屏播报（`DndContext` 的 `accessibility`）改成了中文，E2E 也拿它判断「拖到第几位了」
