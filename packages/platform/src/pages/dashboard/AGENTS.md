## 🔴 读布局失败：错误要看得见，而且**不许编辑**

**症状**（不这么做时）：`GET …/preferences/dashboard.layout` 502，页面照样画出一套卡片 —— 是**默认**布局，
而用户以为「我存的布局没了」；更糟的是这时「编辑工作台」照常可用，改一下点保存，
就拿默认布局把他服务端那份**覆盖掉了**。两步都没有任何报错。

**修法**（`index.tsx`）：读失败时画默认布局 + `dash-layout-error` 错误块（带重试），
`canEdit` 只认「读成功了」（`resolved` 非空）。没存过时接口回 **200 + `value: null`**，不是 404 ——
所以 `error` 只会是真的读失败，不会和「这个人还没存过」混在一个分支里。

**实测证据**：`e2e/tests/dashboard-personalize.spec.ts`「读布局失败」那条用 `page.route` 把那个 GET 打成 502。
两个变异各自当场红：去掉错误块 → 红在「错误块可见」；读失败也允许编辑 → 红在 `toBeDisabled()`。

**保存失败同理**：错误块（`dash-editor-save-error`）留在编辑器里、URL 还是 `edit=true`、草稿不丢。
「保存」写成 `onSettled` 里退出编辑模式的话，失败也弹「已保存」退出去、改动全丢 —— 变异实测那条用例当场红。

⚠️ **「失败」只算「一份数据都没有」的时候**（布局、`me`、权限码、侧边栏四个查询一律只看 `.data`）。React Query 后台重取失败时
**保留上一次的数据、同时置上 `error`** —— 看 `error` 的话，侧边栏一次重取失败整个工作台（连同正在编辑的编辑器）就没了，
布局一次重取失败会在用户自己的布局上方说「先按默认布局显示、不能编辑」。代码评审指出的，没有单独复现过
（这两种重取在 E2E 里不好稳定地触发）。

⚠️ **布局整份认不出来时，「保存」不改东西也要能点**：提示里说的就是「编辑并保存一次就会覆盖它」，
非要先改点什么才能存的话，坏数据就一直覆盖不掉（代码评审指出）。E2E「存的布局整份认不出来」那条：
存一个字符串当布局 → 编辑 → 直接保存 → 刷新后提示消失；变异（保存只看「改过了」）→ 红在 `toBeEnabled()`。

## 🔴 没权限的卡片不渲染 —— 判据必须和**取数接口的守卫**一致，粒度到每个查询

#202 之前非管理员打开首页是一排「没有权限」+「仅超级管理员可见」。现在不能用的卡片不进候选也不渲染，
「系统运行」区（需要你留意 / 服务状态 / 近 14 天访问）对没有对应权限的人**连标题行都不画**。两条容易做错的：

- 🔴 **一个 `Promise.all` 里拼了几个要不同权限的接口，就会整块 403。** 第一期的统计卡一次取用户数 + 角色数 + 公告数：
  部门经理（MANAGER）有 `sys:user:list`、没有 `sys:role:list`，实测 `GET /sys/roles?page=1&size=1` 是 **403**、`/sys/users` 是 200 ——
  绑在一起的话他能看的那一格也拿不到。新版系统运行区因此是**一张卡片一个接口**（`/sys/dashboard/attention|services|visits`），
  `available` 和那个接口的守卫逐张对齐：服务状态是 `DependsSuperUser`（判 `isSuperuser`，没有权限码可判），访问柱状图是 `log:login:list`；
  「需要你留意」三个来源各要各的权限，**后端逐条过滤**，卡片按「任一来源看得见」出现
- ⚠️ **能看数字 ≠ 能点进日志页。** 登录日志列表接口要 `log:login:list`，日志页的**路由守卫**要 `log:login:del`。
  「需要你留意」那一条按前者出现，「看明细」按钮按后者给 —— 只有 list 的人点过去只会落到 /403

🔴 **权限码 / 「我是谁」/ 侧边栏都到齐之前，不算可用卡片、也不合并布局，画骨架。** 两种坏法：
`usePerm().can` 在 codes 还没回来时恒为 `false`，那时算出来的默认布局只有人人都有的几张、等 codes 回来又多出统计卡
（读 `auth/use-perm.ts` 得出的，没专门复现）；更直接的是**拿空集合合并布局** —— 合并出来一张卡片都没有，
页面上是「所有卡片都隐藏了」。实测：E2E「菜单 / 权限还没到齐时是骨架」把侧边栏拖慢 3 秒，`resolveLayout` 不等
`ctxReady` 的写法在布局回来、侧边栏没回来的那段时间里画的就是 `dash-empty`（我自己第一版就是这么写的，评审时翻出来的）。
⚠️ 这条用例第一版用 `toHaveCount(0)` 断言「没出现」，把修复改回去**照样绿** —— 它一上来就满足。
要验「一段时间里一次都没出现」，得先等到窗口开始（布局的响应回来）、确认窗口还在（侧边栏没回来），再不重试地数一次。
「待我处理」「我发起的」「快速发起」的可用性跟着侧边栏走（`inSidebar('/workflow/inbox')`）：审批是插件，没装 / 菜单没授权时
这几张卡片取数必然 404、「全部」也进不去。

## 布局的兼容规则（`layout.ts`，issue #202「1.0 起的兼容约定」）

| 情形 | 行为 |
|---|---|
| 存的里面有不认识 / 现在不能用的卡片 id | 渲染时忽略 |
| 新加的卡片，存的里面没有 | 按它自己的默认显隐 / 宽度排到最后 |
| 单项字段坏了（宽度拼错、显隐不是布尔） | 那一项回落到卡片的默认值，不连累别的项 |
| 整份认不出来（不是对象 / 没有 `cards` 数组） | 默认布局 + `dash-layout-unreadable` 提示 |
| 保存时，存的里面「现在不能用」的卡片 | **原样带回去**排在后面 —— 权限临时被收走时保存一次，权限还回来那张卡片还是原来的设置 |

🔴 所以**卡片 `id` 发出去之后不能改**：改名 = 所有人这张卡片的设置作废、退回默认值排到最后，不会报错。

🔴 **快捷入口的「最多 12 个」只数现在看得见的。** 存的清单里可能排着暂时没权限的 path（原样留着，权限还回来时照旧出现）；
拿 12 去截存的清单，末尾那些就被**静默截掉**了。第一版读和存都按 12 截，代码评审翻出来的。现在读 / 存只有一个防坏数据的
硬上界（64），12 只用在显示和勾选上。`layout.test.ts`「读 / 存都不按显示上限截」：读、存两处各改回截 12，各自当场红。

**实测证据**：`layout.test.ts` 14 条；E2E「存的布局里有不存在的卡片 id / 没权限的卡片」那条
（存了 `no-such-card` + 普通员工没权限的 `visits`，页面照常、两者都不出现，系统运行那一行标题也不画）。
变异：页面不看存的布局（`resolveLayout(null, …)`）→ E2E 5 条红 4 条。

## 编辑模式

- `edit` 进 URL（硬纪律 2），草稿只在组件 state 里、写成 `draft ?? baseline` 两层 —— 后台重取不冲掉没保存的改动；
  刷新时编辑模式还在，草稿回到已保存的那份
- 排序是编辑器里的**竖列表**，不是在卡片网格里直接拖：卡片宽度不一，网格里拖的落点难以预测，
  键盘拖拽在二维网格里也不好用。网格是草稿的实时预览。两组（我的工作 / 系统运行）各一条列表、各一个 `DndContext`，
  不能拖过组界 —— 系统运行区固定画在那一行标题下面，拖过去也画不到那里
- 用了 `@dnd-kit`（platform 的 `package.json` 里声明了，不是借 `packages/ui` 的 —— 根 CLAUDE.md 依赖箭头那条）。
  读屏播报（`DndContext` 的 `accessibility`）改成了中文，E2E 也拿它判断「拖到第几位了」

## 新版布局（#202，设计稿 `Todo.dc.html` / `TodoAdmin.dc.html`）

12 列网格、四档宽度（三分之一 4 · 一半 6 · 三分之二 8 · 整行 12），按**容器**宽度断（`@container/main`）：窄的时候三分之一 / 一半
占半行、三分之二占整行，再窄一律整行。默认：待我处理 三分之二 + 我发起的 三分之一；快速发起 / 常用入口 / 和我有关的消息 各三分之一；
公告默认**不显示**（顶栏横幅 / 弹窗 / 铃铛已经覆盖「有新公告」，「自定义」里能打开）；系统运行区 需要你留意 + 服务状态 各一半、访问整行。
「常用入口」「和我有关的消息」沿用第一期的 id `quick-links` / `unread`，存过的布局照认。

- 🔴 **大标题那句数字和「待我处理」是同一份 query（`deskTodoQuery`），取数失败要说出来**：不能退成「手上没有要处理的事」——
  那是一句假话。N = 待审批 + 退回给我（不含草稿，同卡片的「全部」），0 件时说平静的那句，不说「你有 0 件事」。
  实测：E2E「待我处理用真数据」断言整句「你有 2 件事等着处理，其中 1 件加急」；变异（加急数恒 0）当场红。
  ⚠️ 失败那一支（「待办数量没取到」）**没有** E2E
- 🔴 **步骤条只画拿得到的，名字照后端给的**：一步只有一个人办时是**人名**、多人是节点名（设计稿就是「发起 → 赵磊 → 财务」）；
  推演不了（`next_steps: null`，条件用到发起人看不到的字段）画一个「…」，不编后面的步骤。
  我第一版 E2E 照「节点名」写的断言，跑出来是人名 —— 后端 `_steps` 的注释写着规则，读漏了。变异（不画推演出来的那几步）当场红
- 「待我处理」的分段（`todo`）进 URL（硬纪律 2），「处理」/「去修改」就地开审批详情抽屉（`wf`），不跳审批中心。
  超时胶囊按节点的**超时动作**出字（「后自动同意 / 驳回 / 提醒」），不是一律「快到期」。三条各有变异当场红
- ⚠️ 「退回给我」的数只数**取回来的那一页**（`DESK_TODO_SIZE` = 50 条）；待办超过一页时它偏小、「待审批」偏大，总数仍是后端的 total。
  读代码得出的，没有造过 50 条以上的待办去看
- 访问柱状图是固定 viewBox 的内联 SVG（理由同监控页的 `Sparkline`：隐藏 tab 宽度 0，`ResponsiveContainer` 量不出来）。
  画布宽度按「整行卡片在 1440 宽的屏上」取 940：照设计稿的 710 画，1440 截图里坐标轴的字被放大到约 17px
- ⚠️ E2E 现建的流程定义有过实例就删不掉，会出现在**所有人**的「快速发起」里（截图时 admin 的四个格子全是 `E2E 采购 …`）——
  `dashboard-personalize.spec.ts` 收尾时把它停用
